# Агентство: выберите результат и дайте задачу агенту

**[Открыть каталог](https://vkirill.github.io/agency-router/) · [Описать свою задачу](https://vkirill.github.io/agency-router/start.html) · [Операции и модели](https://vkirill.github.io/agency-router/models.html)**

80 конечных результатов, 128 отдельных операций, маршруты работы, структура материалов и два навыка. Версия дистрибуции **0.8.0**. Это библиотека поручений для работы с AI: можно начать одним агентом в обычном чате. BB, несколько подписок и файловая система для этого не обязательны.

## Самый простой способ

1. Откройте [форму поручения](https://vkirill.github.io/agency-router/start.html).
2. Выберите результат, опишите свою ситуацию и перечислите материалы. Если чего-то нет — так и напишите.
3. Нажмите «Скопировать поручение», вставьте его в свой AI-чат и приложите упомянутые файлы.
4. Агент выполнит доступную работу, уточнит существенные пробелы и назовёт следующий шаг.

Например, выберите **«Бриф и список вопросов клиенту»** и напишите:

> Нужен сайт стоматологии в Казани. Хотим получать заявки на имплантацию. Есть старый сайт и прайс, бюджета пока нет. Подготовь бриф и вопросы для первого разговора с владельцем. Результат в чат.

На выходе: подтверждённые факты, цель и границы, неизвестное, вопросы по приоритетам. Не нужно заранее создавать готовый бриф, бренд-стратегию или `PROJECT.md`. Задача помогает их подготовить. Если переданных сведений достаточно, агент начинает без обязательного опроса.

Для **«Созвон → решения и задачи»** понадобятся запись, расшифровка или заметки. Без них агент попросит исходник или ваш пересказ; если встреча ещё впереди — предложит подготовить вопросы. Отсутствующее содержание встречи он не придумывает.

## Можно просто дать ссылку своему агенту

Скопируйте и замените текст в квадратных скобках:

```text
Прочитай README и AGENTS.md репозитория:
https://github.com/VKirill/agency-router

Возьми поручение «Созвон → решения и задачи» (BRIEF-03).
Моя задача: [что нужно получить и для кого].
Материалы: [вставленный текст / ссылки / прикреплённые файлы / пока нет].
Ограничения: [известный срок, язык, формат; можно написать «не заданы»].
Результат: [в чат / в выбранную папку проекта].

Найди поручение в prompts/index.json и прочитай его PROMPT.md.
Если работаем в файлах, скопируй пакет по manifest.json и объясни,
какие входы ещё нужны. Начни одним агентом. Не устанавливай все
дополнительные навыки и не запускай внешние действия автоматически.
```

Если агент не умеет открывать GitHub, используйте текст из формы или прикрепите выбранный `PROMPT.md`. Это самостоятельное поручение; без установки навыков можно получить ответ в чат. Формальную проверку файла навыком такой агент не должен имитировать.

## Где лежат поручения и что копировать — инструкция агенту

1. Прочитай пользовательский запрос и местные правила проекта. Различай «подготовь/скопируй» и «выполни». По просьбе скопировать сначала создай редактируемый пакет; само копирование не означает запуск.
2. Найди точный ID или название в [prompts/index.json](prompts/index.json). Там есть `prompt`, `recipe`, `manifest`. Точное название **«Созвон → решения и задачи» → BRIEF-03**. Расширенный пакет **«Созвон → протокол, решения и задачи» → OUT-001** включает маршрут. При неоднозначности покажи варианты с результатами.
3. Прочитай `prompts/<ID>/PROMPT.md`: это готовый текст с блоком **«Мои данные»**. `recipe.json` хранит входы, минимально достаточный старт, этапы, приёмку и условные подготовительные поручения. Не путай рецепт `agency-recipe/1.0` с BB-контрактом модели `contract_version=0.2`: это разные схемы.
4. Для ответа в чат перенеси текст поручения и пользовательские данные. Для файлового режима выясни реальный выбранный корень проекта, проверь существующую структуру и прочитай `manifest.json`. Копируй только явно перечисленные в нём файлы/папки.
5. Вместе с выбранным поручением пакет содержит **оба навыка целиком** (`SKILL.md`, `references/`, `assets/`, `scripts/`, зависимости), памятку `_kit/README.md`, а для конечного результата — его `route.json`. Одного `SKILL.md` недостаточно: в нём относительные ссылки на справки и схемы.
6. Профильные навыки в `optional_skills` — условные кандидаты, они **не входят в этот репозиторий**. Проверь, нужен ли конкретный навык для текущего этапа и доступен ли он. Отсутствующее умение можно выполнить другим доступным инструментом с честной проверкой либо назвать блокером. Не заявляй использование ненайденного навыка. Установка сторонних пакетов — отдельное действие в рамках полномочий пользователя.
7. Прими свободное описание вместо отсутствующего оформления. Для реальных записей, метрик, кода и доказательств нужны соответствующие исходники. Для пробела верни: **чего нет → зачем → текст/файл/доступ, который подходит → точное предыдущее поручение, если оно известно**. Ссылки `preparation_options` условны; не запускай всю цепочку по умолчанию.
8. Подготовь исполнение по доступным возможностям. Не подставляй названия моделей из примеров как заведомо доступные. Выбор модели и режима происходит в настройках среды, а не фразой в промпте. Выполни разрешённые этапы, проверь результат и передай ограничения/следующий шаг.

Полный каталог остаётся в дистрибуции. Не копируй все 208 поручений, чужие клиентские данные, историю чатов, ключи или настройки личной машины в проект пользователя. Skill `model-task-prompts` включает свой справочный каталог процессов как зависимость; загружай из него только выбранный маршрут.

## Копирование в папку проекта одной командой

Нужен Node.js 20+; внешних Node-пакетов нет. Команды выполняются в скачанном репозитории:

```sh
node scripts/copy-task.mjs find "Созвон → решения и задачи"
node scripts/copy-task.mjs copy BRIEF-03 /absolute/path/to/existing-project call-decisions
```

Замените путь на **существующую папку своего проекта**. Идентификатор задачи — латиница, цифры и дефисы. Скрипт создаст:

```text
<project>/work/tasks/call-decisions/
  request.md           # сюда пользователь/агент вписывает свою задачу и исходники
  PROMPT.md            # поручение с правилами выполнения
  recipe.json          # структурированное описание выбранной операции
  package.json         # выбранный проект, ID, источник пакета; status=draft
  route.json           # только у OUT-пакетов, этапы и зависимости
  _kit/
    README.md          # инструкция исполнителю
    skills/
      model-task-prompts/
      agency-artifacts/
```

Скрипт не перезаписывает существующую папку задачи, не меняет корневые инструкции, не устанавливает навыки глобально и не запускает модели. Для применения навыка достаточно прочитать его из `_kit`; если ваша среда поддерживает установку навыков, перенесите две полные папки в её документированный каталог, предварительно проверив существующие версии.

После копирования скажите агенту: «Прочитай `request.md`, `PROMPT.md` и `_kit/README.md` в этой задаче; выполни доступные этапы». Настоящие результаты сохраняются в папке направления проекта, а запись задачи ссылается на них. Уже принятые контракты Reels, Insights и кодового репозитория сохраняются.

## Что такое PROJECT.md и когда он нужен

Это краткий паспорт: цель, продукт, аудитория, границы, ответственные, этап, важные решения и навигация. `project.json` — машинная карта путей и версий общих знаний. Для первого брифа в чате они не обязательны.

Агент создаёт черновик при начале продолжающейся работы в выбранной папке проекта. Обновляет после подтверждённого изменения контекста или канонических ссылок, сохраняя основание и версии. Обычная готовая статья остаётся в `content/`, а не целиком в паспорте.

Читайте [жизненный цикл паспорта](skills/model-task-prompts/references/project-passport.md), [шаблон PROJECT.md](templates/PROJECT.example.md) и [карту отделов](skills/model-task-prompts/references/agency-project.md).

## Модели, исследования и границы

Распределение — исходная гипотеза для пилота, **не измеренный рейтинг стоимости или качества на заказах**. BB-привязки моделей — снимок конкретного каталога на 2026-09-13. Они не гарантируют существование такого ID в другом сервисе, наличие подписки, инструмента или одинакового режима мышления. Проверяйте живой каталог своей среды; обычный чат не требует BB-компилятора.

Политика этого роутера: Luna только High/Max + Fast, иначе другая подходящая модель. Это пользовательское предпочтение. Параметры разных провайдеров не взаимозаменяемы. Подписка не означает API-доступ; эффективные настройки проверяются при запуске.

Источники и тип доказательства — [исследование практик](docs/agency-outcome-research.md). Кейсы поставщиков и рассказы Reddit показывают варианты применения, но не доказывают доход или причинность. Маршруты — инструкции для исполнителя; сайт не является сервисом автономного исполнения. Отправка писем, публикации, рекламные бюджеты и релизы выполняются только в пределах реального поручения.

## Проверка и обновление сайта

```sh
node scripts/build.mjs
node scripts/test.mjs
node skills/model-task-prompts/scripts/test.cjs
node skills/model-task-prompts/scripts/test-project.cjs
python3 -m venv .venv
.venv/bin/pip install -r skills/agency-artifacts/requirements.txt
.venv/bin/python skills/agency-artifacts/scripts/test_artifact.py
.venv/bin/python scripts/test-metadata.py
```

Редактируйте `catalog/`, `scripts/recipes.mjs` и `site-src/`, затем пересобирайте. `prompts/` и три HTML — результаты сборки. Специальные правила старта добавляются в рецепты, а не только в текст сайта. Проверки покрывают структуру и копирование; они не означают, что все 208 бизнес-задач выполнены на клиентах.

GitHub Pages публикует `main` из корня (`/`); `.nojekyll` включает обычную раздачу статических файлов. После push GitHub обновляет сайт. [Настройка источника публикации — GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). Откат: вернуть проверенную версию Git отдельным revert-коммитом и дождаться публикации. Сайт не хранит введённые задания и не отправляет их моделям.

Правила составления исполнимых навыков и связь с официальными руководствами — [skill-authoring.md](docs/skill-authoring.md).
