Сначала направление, затем задача

PROJECT.md и project.json — вход в проект. Общие принятые знания используются всеми отделами. У задачи остаются запуск, источники и проверки, а готовые материалы живут в своём направлении.

Например, Facebook-реклама читает brand/VOICE.md и research/audience/PAINS.md. Бриф иллюстраций к статье живёт в design/requests/<id>/BRIEF.md; статья связывает слоты с готовыми asset IDs.

Единый паспорт рабочего документа
Навык agency-artifacts · схема agency-artifact/1.0. Markdown — YAML-шапка; JSON — объект _meta. Статус документа и статус задачи различаются.
Принадлежность
project_id, department, topic, task_ref и owner — чей это документ, для какой работы и кто отвечает.
Результат и история
artifact_id, artifact_type, title, version, created_at, updated_at. ID сохраняется, содержательная правка повышает версию.
Статус и приёмка
draft → in_review → approved; доработка — changes_requested. blocked содержит причину; superseded и archived сохраняют историю.
approved требует review с принимающим, датой и ссылкой на решение для этой версии. Он не означает, что задача завершена.
Источники и формат
source_refs, depends_on с версиями, access и профильные extensions. Секреты в метаданные не помещаются.
Raw, JSONL, изображения и закрытые JSON-схемы сохраняются. Рядом — имя-файла.meta.json с target. У SKILL.md остаётся собственная шапка.
Образец Markdown
Заготовка: ID, даты и реальные привязки заполнить при создании. Статус draft не является одобрением.
Образец JSON
Проверка: python scripts/artifact.py validate FILE. Создание нового draft: python scripts/artifact.py init FILE --format md --title TITLE --department content. Валидатор не удостоверяет полномочия и не запускает публикацию.
Архитектура 0.3 · схема для планирования, не запущенный workflow. Все решения и результаты здесь — этапы шаблона.
