
# Как составлять поручения моделям

Версия 0.3.0, проверка документации 2026-09-13. Навык `model-task-prompts`: единый контракт + короткая адаптация выбранного семейства. Поручение оркестратору и поручение конкретному этапу теперь можно выбрать на странице роутера. Кнопка выдаёт черновик: цель и приёмка готовы, входы, реальные пути и доступы заполняются перед запуском.

| Семейство | Что меняется в поручении |
|---|---|
| GPT-5.6 Luna/Terra/Sol | Короткое задание без повторяющихся правил; ясные полномочия и обязательное содержание результата. Luna High/Max Fast — правило владельца |
| GPT Astra | Автономность в разрешённой области, существенные неизвестные и соразмерные проверки; без обязательного длинного ритуала |
| Claude | Контекст и требования; Opus без универсальных циклов перепроверки; Fable — явный поиск актуальных сведений и передача состояния на длинной работе |
| Gemini | Чёткая структура, идентификаторы мультимодальных входов, вопрос после длинного контекста, нужный формат |
| Grok | Общий контракт задачи, воспроизводимость для кода и схема для данных; возможности API не приписываются Cursor |

Источники: [GPT-5.6](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6), [Astra](https://developers.openai.com/api/docs/guides/latest-model), [Claude](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), [Opus](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5), [Fable](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1), [Gemini](https://ai.google.dev/gemini-api/docs/prompting-strategies), [Grok reasoning](https://docs.x.ai/developers/model-capabilities/text/reasoning), [Grok Structured Outputs](https://docs.x.ai/developers/model-capabilities/text/structured-outputs). Прочитаны сами страницы, не только поисковые сниппеты. Отдельного доказанного универсального рецепта текстового промптинга Grok 4.6 не заявляем.

Практические правила: цель → входы → результат → приёмка → полномочия → инструменты → пути. Документы и выгрузки — данные, а не инструкции. Просить краткие основания и проверяемые доказательства, не внутреннюю цепочку рассуждений. Не назначать дополнительные согласования уже разрешённым действиям. Не требовать повторной самопроверки каждой мелочи. Не включать в каждое задание все справки по моделям.

Конфигурация provider/model/effort/serviceTier хранится отдельно и проверяется у исполнителя. Команда в промпте не активирует Fast, Structured Outputs, поиск или доступ к сервису. Для API структурный формат задаётся настройками, если поддерживается; в CLI результат проверяется валидатором. Промпт и среда исполнения — разные уровни.

[Хранение и источники](agency-storage.md), [выбор моделей](model-router.md), [страница](../models.html). Два переносимых навыка лежат в `skills/` этого репозитория; установка и копирование описаны в корневом README.

В 0.2.0 добавлены [отделы, знания и процессы](agency-project.md): общие материалы читаются по knowledge_refs; передача включает версии и конкретный бриф; выбранные навыки проверяются по фактическому SKILL.md; gates привязаны к версии результата. Примеры — заготовки, а не подтверждённые клиентские данные.

Навык agency-artifacts задаёт единые метаданные сохраняемых файлов; см. [стандарт](artifact-standard.md). Для статьи дополнительно visual-plan и краткие ТЗ; при принятом нуле слотов дизайнер пропускается.
