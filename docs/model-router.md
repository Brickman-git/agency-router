## Быстрый выбор

| Операция | Обычный старт | Когда усилить / заменить |
|---|---|---|
| Извлечение, нормализация, форматирование | GPT‑6.1 Sol High | XHigh при ошибке смысла; Gemini Medium для мультимодальности/резерва |
| Сбор и сверка нескольких источников | GPT‑6.1 Sol High с поиском | XHigh для трудного противоречия; отсутствие поиска лечить подключением |
| Дипресерч, большой корпус с противоречиями | GPT‑6.1 Sol High | XHigh для трудного узла; Fable Low — кандидат сравнительного прогона |
| Декомпозиция, стратегия, ведение проекта | GPT‑6.1 Sol High | XHigh при недостигнутой приёмке; Fable Low — резерв |
| Текст и редактура по ясному брифу | Opus 5 Low | Opus Medium/High для сложного материала; GPT‑6.1 Sol High — резерв |
| Идеи, черновые варианты | Gemini Flash Low | Opus Low/Medium с критериями разнообразия |
| Обычный код, сайты, скрипты | Grok 4.6 High | GPT‑6.1 Sol High — резерв, XHigh для трудного дефекта |
| Маленькая правка с точной проверкой | Grok Medium / GPT‑6.1 Sol High | По фактической ошибке, не размеру названия модели |
| Расчёты и диагностика метрик | GPT‑6.1 Sol High + код/формулы | XHigh для трудной гипотезы; независимый расчёт |
| Проверка по рубрике, визуальный разбор | Gemini Flash Medium | GPT‑6.1 Sol High для формальной проверки; Opus Medium для содержательного кода |
| Действия в приложениях | GPT‑6.1 Sol High с нужным инструментом | XHigh для сложных зависимых действий; проверить целевое подключение |

Точные назначения 11 профилей и исключения находятся в JSON. Все активные Codex-конфигурации, включая контракты, overrides, резерв и рецензирование, используют `gpt-6.1-sol` с `high`. Сложные случаи усиливаются до `xhigh`. Оркестратор сборного заказа — GPT‑6.1 Sol High. Luna, Astra и GPT‑5.6 Sol/Terra исключены из активных привязок. Одна простая задача остаётся у одного исполнителя. Соседние совместимые операции объединять; независимый рецензент нужен при цене ошибки или непроверяемом автоматически критерии, а не на каждой стрелке.

## Экономика и лимиты

Сравнивать стоимость **принятого результата**: все вызовы, повторные попытки, время, инструменты и доработка человеком. Цена за миллион токенов не равна расходу подписки. Fast может иметь собственную тарификацию; высокий effort маленькой модели не гарантирует меньшего времени. Не переводить задачу на платный API автоматически.

Порядок решения: доступный инструмент → требуемое качество → соблюдение срока → известный остаток подписки → измеренный расход. Между одинаково подходящими кандидатами распределять новые задачи по свободному запасу квоты; если квота неизвестна, записать unknown и чередовать подходящие семейства. Не назначать 25% каждому ценой качества. GPT берёт данные/синтез, Grok код, Claude текст/сложные альтернативы, Gemini варианты/визуал/проверки; роли перекрываются.

GPT‑6.1 Sol High/XHigh и Fable Low включены в текущий план сравнения. OpenAI описывает [GPT‑6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) как модель с качеством, близким к Astra, при меньшей стоимости. Это основание для выбора, а не измеренное равенство на наших заказах. Высокий effort может увеличивать время и расход токенов; сравнивать полный цикл принятия результата. Claude, Gemini и Grok сохраняют прежние роли.

Эскалация: сначала уточнить входы/инструменты; после повторения той же ошибки сменить метод или исполнителя. Для трудного решения и недостигнутой приёмки — GPT‑6.1 Sol XHigh. Fable Low сравнивать с Sol на сложном синтезе; Fable High для длинной трудной работы после проверки выгоды. `ultra`/`ultracode` не сравнивать как обычный effort: это специальные режимы обёртки.

**Codex: GPT‑6.1 Sol High; усиление XHigh, serviceTier=default.** Обязательного Fast нет. Это согласованная политика владельца от 2026-09-30; не результат бизнес-бенчмарка.

## Подключения

| Семейство | BB provider | model IDs |
|---|---|---|
| GPT | codex | gpt-6.1-sol (High / XHigh) |
| Claude | claude-code | claude-opus-5[1m], claude-fable-5-1, claude-sonnet-5 |
| Grok | acp-cursor | grok-4.6 |
| Gemini | acp-antigravity | gemini-3.8-flash |

GPT‑6.1 Sol доступна в текущей среде Codex; успешный запуск через BB отдельно не проверен. Привязки остальных провайдеров сохранены из каталога Mac mini от 2026-09-13. Каталог ≠ успешный инструментальный запуск или известная квота. Grok здесь работает через Cursor, это не автоматическое использование подписки Grok.com. Gemini требует проверки фактической сессии и доступных инструментов; прежнее предупреждение Antigravity нельзя считать снятым только по списку моделей. Соннет доступен в каталоге, но преимущество перед Opus Low/Fable Low здесь не установлено.

## Поручение и сохранение результата

Навык `model-task-prompts` составляет общий контракт и добавляет только справку выбранной модели. На странице выбрать «оркестратору» либо отдельную стадию, затем скопировать. Заполнить реальные входы, права, пути и binding инструментов. Сохранить prompt.md и requested/effective config в runs; источники в sources.json, сырые выгрузки в raw, данные в data, канонический результат в папке отдела со ссылкой из artifacts.json, проверки в checks. [Полный контракт](agency-storage.md) содержит пример SEO и карту файлов 16 направлений.

Перед запуском проверить модель/effort/serviceTier, чтение входов и нужные capabilities. Перед приёмкой — результат конкретной задачи. После — зафиксировать реальное время, попытки, usage и известный расход квоты. Следующий шаг для доказанного распределения — [пилот](pilot-plan.md); текущая версия сравнивает GPT‑6.1 Sol High/XHigh с подходящими кандидатами других провайдеров; не выдавать план за выполненный эксперимент.


## Структура агентства и процессы

[Карта проекта](agency-project.md) и [интерактивная схема](../index.html) связывают 16 направлений, общие знания, роли и навыки. Сначала PROJECT.md → project.json → knowledge_refs, затем отдел и конкретная задача. В каждом поручении заданы work_context, context_requirements, skills и gates; недостающий вход направляется владельцу знаний.

Три разобранных процесса: сайт до production и SEO-клиентов; статья с двумя иллюстрациями; Facebook-кампания. Каждый этап содержит входы, папки результата, приёмку и обратный маршрут. Человек решает вопросы объёма, концепции, production и следующего бизнес-цикла; действующие решения переиспользуются в своём объёме. Codex-назначения обновлены по политике владельца; сравнительный пилот стоимости и качества ещё необходим.

[80 конечных результатов](agency-outcomes.md), [источники практик](agency-outcome-research.md), [стандарт артефактов](artifact-standard.md). В интерактивной карте есть поиск по результатам и 16 групп; статья сдаётся с визуальным планом 0…N и краткими ТЗ, затем проходит ревью и сборку.

Первая [учебная серия High/XHigh](model-pilot-2026-09-30.md): шесть запусков, все прошли приёмку. Полный клиентский пилот и сравнение с другими семействами остаются отдельной работой.
