# Как устроена исполнимая инструкция

Обновлено 2026-09-14. Это стандарт оформления навыков этой библиотеки. Общий формат Agent Skills задаёт упаковку; действия и критерии ниже — наш контракт качества.

## Что взято из руководств

| Основание | Применение в библиотеке |
|---|---|
| [Anthropic: Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) | Короткое назначение, условное чтение справок, шаги для сложного процесса, проверка → исправление → повторная проверка, сценарии применения |
| [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills) | SKILL.md с name/description; инструкции загружаются по назначению, ресурсы — по необходимости |
| [OpenAI: GPT-5.2 Prompting Guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5-2_prompting_guide) | Явные границы задачи и формат ответа, различение обязательных/необязательных полей, обработка отсутствующих данных |
| [Agent Skills specification](https://agentskills.io/specification) | Совместимая YAML-шапка, относительные ресурсы, необязательные compatibility и metadata |

Руководство GPT-5.2 здесь использовано как источник общих приёмов постановки задачи. Его параметры и заявленные результаты не выдаются за проверенные свойства GPT-5.6/Astra. Ни один источник не предписывает единственную обязательную Markdown/XML-структуру тела навыка и не гарантирует одинаковое поведение всех моделей.

## Что обязательно в наших навыках

1. **Область применения.** Определяет наблюдаемый запрос и близкий случай, когда навык не нужен.
2. **Входы.** Названы фактические материалы и допустимые альтернативы. Отсутствие оформления не приравнено к отсутствию данных.
3. **Действия.** Каждое существенное правило отвечает на вопрос, что сделать с каким объектом. У ветвления указаны условие и обе реакции.
4. **Выход.** Названы форма результата и поля, если они существенны.
5. **Проверка.** Есть критерий, реакция на ошибку и условие окончания. Недоступный валидатор не объявляется выполненным.
6. **Зависимости.** Модельные/платформенные ветки включаются только в нужной среде; навыки и инструменты не считаются установленными по упоминанию.

Названия разделов допускается адаптировать к операции. Упорядоченный алгоритм нужен для хрупких действий; творческим задачам задаются цель, ограничения и критерии без выдуманного единственного метода.

## Пример переработки

Общее пожелание:

> Поддерживай актуальность и структурированность документов.

Инструкция:

> Если подтверждена смена владельца проекта, обнови ответственного в PROJECT.md и ссылку на основание. Меняй владельца knowledge_refs только для затронутых знаний. Сохрани предыдущую принятую версию; проверь ссылки. Обычное завершение статьи не является причиной править паспорт.

## Шапка навыка

```yaml
---
name: example-skill
description: "Описывает конкретное действие и запросы, при которых навык нужен."
compatibility: "Только реальные требования среды, если они есть."
metadata:
  version: "1.0.0"
---
```

Не добавлять сюда project_id, статус клиентского документа или department. Они относятся к схеме создаваемого артефакта. Не включать расширения только одного провайдера в переносимое ядро. Не вводить дополнительный XML/JSON только ради внешнего вида.

## Проверка качества

Автоматические проверки схемы и скриптов не заменяют проверку поведения. Для обновления использованы три изолированных сценария: промпт обычному агенту без BB, выполнение брифа без паспорта, метаданные вне BB при закрытой JSON-схеме и отсутствии Python. Сравнение прежней инструкции выполнено в сценариях промпта и метаданных.

Эти пробы выполнены доступным агентом проверки. Отдельные нативные запуски Claude Code, Grok и Gemini для этой редакции не проводились; одинаковое выполнение всеми моделями не заявляется. Публикуемые версии правил, схем и компилятора различаются: новая инструкция не меняет автоматически старую машинную схему.
