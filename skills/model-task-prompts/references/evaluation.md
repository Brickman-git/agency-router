# Проверка навыка

Версия 0.1.1. Автоматические проверки: `node scripts/test.cjs` — восемь поддерживаемых имён, запрет недопустимых Luna effort/Fast, разделители данных, отсутствующие поля, draft/ready, создание/отказ от перезаписи и выхода через symlink. Это проверки компилятора, не benchmark интеллекта.

Поведенческие пробы в свежих чатах: поручение Luna на проверку SEO CSV без данных; явный вызов навыка для Fable/Gemini на сверку утверждений; близкий вопрос «модель или инструмент» без просьбы составить промпт. Контрольная проба проведена до установки. Критерии: чтение нужных справок, отсутствие выдуманных доступов/данных, сохранение Luna High/Max Fast, отдельная настройка запуска, конкретная приёмка, отсутствие самовольного исполнения.

Наблюдение: без явного имени автоматическое подключение в одной пробе не сработало. Близкий вопрос не вызвал ненужной загрузки. Поэтому использовать явный вызов `model-task-prompts` или общий компилятор страницы. Не обещать автоматическую активацию во всех чатах. Подробные результаты хранятся у владельца эксперимента отдельно от переносимого навыка.

При обновлении: повторить одинаковые задачи с прежним/новым промптом на той же модели, фиксировать точный режим, исходные файлы и результаты. Измерять принятие, существенные ошибки, время полного цикла, повторы и доступный usage; сравнение текста одного ответа не доказывает экономию подписки. Для нового семейства/версии проверить реальные задачи этого семейства, а не только работу компилятора.

Проба первой версии выявила смешение API provider names и BB IDs. В 0.1.1 введена строгая проверка привязок; повтор явного запроса выдал корректные BB-конфигурации. Автоматических проверок — 22.


Обновление 0.2.0: 61 дополнительная автоматическая проверка дерева знаний, трёх процессов, зависимостей, skill bindings и решений по версиям. Поведенческая серия: baseline и две первые пробы дали прежний контракт; их не засчитываем как подтверждение 0.2. Две повторные пробы с явно указанной актуальной копией навыка подтвердили отделы/knowledge_refs, передачу статьи дизайнеру и маршрут сайта с отдельными метриками посещений/клиентов. Причина выбора старой копии в ранних пробах не установлена. Это оценка поручений; реальные клиентские изображения, сайт и SEO-результаты не создавались.


Обновление 0.3.0: каталог конечных результатов и редакторский визуальный план 0…N. Три свежие пробы (baseline, актуальная копия, принятый ноль визуалов/self-review) проверяли содержательные свойства поручения, не машинную валидность возвращённого агентом YAML. Baseline по прямому запросу также предложил 0…N; улучшение — конкретные краткие ТЗ, anchors/wrap/mobile и финальное preview-review. Структурные проверки каталога и ролевых передач отделены от бизнес-пилота. Навык agency-artifacts применяется по условию создания рабочего документа.
