# Claude: Opus, Sonnet, Fable

Проверено 2026-09-13. [Общие практики](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices): явно описать результат и контекст, использовать подходящие разнообразные примеры при необходимости; разделять инструкции и данные. В длинном контексте документы предшествуют конкретному вопросу, сохраняются метаданные источника. Это помогает структуре, но не гарантирует истинность.

[Opus 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5): убрать общие команды многократно перепроверять себя и обязательно запускать проверяющего. Ограничить объём изменений. Локальная приёмка при этом остаётся: нужный тест или ссылка на источник — свойство результата, не ритуал.

[Fable 5.1](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1): проверить разные effort на своём наборе; Low заслуживает сравнения, но может реже обращаться к поиску. Для актуальных утверждений прямо требовать прочитать источник. На длинной работе обозначить обновления прогресса и сохранение решений, ограничений и точных ссылок при передаче контекста. Предпочитать точечные правки, не расширять задачу соседними улучшениями. Высокий effort для длинного результата может увеличить задержку. Отображение прогресса также зависит от клиента/API, один промпт не гарантирует его в UI.

Локальный старт: Opus Low для редакторского результата с ясным брифом; Fable Low — сравнительный кандидат сложного синтеза, High — при доказанной необходимости. Не переносить особенности Opus на Sonnet как проверенный факт: для Sonnet сначала общие правила, затем свежая профильная документация при проблеме.
